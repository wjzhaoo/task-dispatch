# 统一 Web 控制台

## 启动

双击仓库根目录 `dashboard.bat`（或 `web-console.bat`），或执行：

```powershell
node runtime/web-console.cjs
node runtime/web-console.cjs --port 43187
```

无参数启动直接打开浏览器统一控制台主页，默认端口 **43187**，被占用时自动顺延；主页已在运行时不会重复启动，而是复用该进程并重新打开一条登录链接（60 秒内有效）。关闭启动器窗口只停止控制台，不影响任何项目服务。即使系统没有项目也能进入主页，页面每 2 秒重新读取目录和任务计数；项目首次接入、空项目新增任务后都无需重启页面。项目统一从主页选择，Web 启动器不再接受 `--data`/`--workspace`；原命令行菜单保留为 `dashboard.bat --cli`。

主页读取用户总目录中的项目目录表（Windows：`%USERPROFILE%\.task-dispatch-service\service-registry.json`），逐项目显示卡片，表里有多少项目就显示多少张。目录表只登记项目 ID、数据目录与工作区路径，不含令牌。控制台运行记录保存在同目录的 `console.json`。只读取此目录，不再读取或导入旧 AppData 索引；项目重新接入时登记到新索引。

控制台顶栏右侧操作区最左的灰色徽标显示本机正在运行的控制台服务版本（如 `v0.7.5`），来自 `/catalog/api/version`，登录前后都可见，用于核对页面跑的是哪一份代码；进入项目后状态栏的「运行版本」是该项目服务自己的版本，两者可以不同（项目服务未重启时仍是旧版本）。

点击卡片的「进入控制台」后仍在同一端口内打开项目控制台（hash 路由 `#/p/<key>`），不再跳转其他端口：目录服务兼任网关，在服务端用一次性票据换取该项目服务的管理会话（仅内存保存），把总览、事件、SSE 实时流和管理命令同源转发给浏览器；长期管理员令牌不会交给网页。项目控制台只承载单个项目，分「总览 / 任务 / 事件」三个页签，常用操作直接放在项目页，简单操作点击即执行，归档、恢复归档与删除保留在「后台控制」；跨项目聚合只保留在主页。

每个项目跑自己独立的服务进程，所以主页卡片直接提供进程控制：未运行显示「启动服务」，运行中显示「停止服务」和「重启服务」。停止与重启要再点一次确认，确认态上会写明当前风险提示（在途 N · 未结算 N）。网关按 `endpoint.json` 记录的 pid 等待服务真正退出，超过 15 秒未退出直接报错，不谎报成功；非桌面模式有无人值守执行在途时拒绝停止，桌面端允许停止但会告知有多少已领取未结算——这些端必须在各自会话重新接入。卡片同时显示该项目服务自身的运行版本，与控制台版本不一致时标记「服务仍为旧版本，待重启」，用来判断改了 `runtime/` 之后还有哪些项目没加载新代码。

## 从 Web 创建目标并邀请成员

1. 主页点击「创建目标」，填写目标名称、目标与验收要求、已有目录的绝对路径。项目内点击「新增目标」时目录自动沿用。一个目录对应一个持续使用的项目，可以不断追加目标。
2. 默认团队为“大脑＋独立初审端＋一名执行员”。执行员编号、能力标签与职责放在「高级成员设置」中，支持 1–20 名执行员；默认 general 表示通用能力，不预设强模型。实际平台和模型由接收会话选择。
3. 点击「创建目标」只保存待开始目标，成员接入不会启动任务。全部成员就绪后，在项目页或目标卡片点击「开始」才执行；有活动目标时点击「加入队列」，排在队尾。项目页直接提供开始、继续、暂停、结束、重新开启及存储清理入口；成员卡片提供改绑、取消改绑和解绑，任务详情提供重试、改派、追加额度、唤醒和重置。开始、继续、暂停、重新开启、再次提醒及取消改绑邀请点击即执行；改派和追加额度仅填写必要参数，成员配置直接保存；结束、停止、取消目标、解绑、归档、删除和重置保留一次确认，无需填写原因、输入 ID 或重复勾选；归档、恢复归档和删除保留在后台控制。执行中的目标、阶段和验收要求不受新增目标影响。
4. 「项目成员」只为缺少的成员提供「复制加入邀请」；选择接收会话的实际平台并粘贴到该项目的会话。成员可同时加入，执行员或初审端可以先于大脑接入。已有合法绑定直接复用，不因新增目标重新连接。

`connect` 包含独立凭据保存、指定平台的身份核验、续接配置与自动待命；返回 `parked:true` 即可结束当前模型回合，无需额外查询状态或配置唤醒。返回正式 job 则直接处理。Web 已保存成员配置，连接回执标注 `peerSetupManagedBy: web`，大脑不重复 `staff` 或生成邀请；用户已经明确指定平台时直接复用该选择，缺少真实会话信息时才补齐，禁止按目录猜测会话或跨平台探测。

首次邀请按成员保持同一标识，刷新或切换平台不会重建，不能替换已绑定的其他客户端；换人使用成员卡片的显式改绑。只有没有活动目标及未结算工作时才能「调整成员」，服务也会再次检查。新增目标始终沿用现有团队，不会应用创建请求中另一套成员配置。

创建提交按持久化 `commandId` 去重：相同内容重试返回同一个 `goalId`，新编号表示一个新目标；同编号不同内容会报错。重复开始不创建额外规划或唤醒。页面不会扫描陌生会话或自动另开模型会话；接收端需能执行本地客户端，本轮仅支持同机。

### 目标队列与完成

目标与大脑拆分的执行任务独立保存，执行任务和阶段均记录 `goalId`，阶段终审不能混入其他目标。

| 目标状态 | 行为 |
| --- | --- |
| 待开始 | 仅保存，尚未授权，不占执行队列 |
| 排队中 | 已授权，按入队顺序等待，可取消并保留记录 |
| 执行中 | 当前唯一活动目标 |
| 阻塞 | 保留当前目标并暂停后续目标，大脑继续处理阻塞 |
| 已完成 | 大脑明确提交完成与验收摘要，所有任务、阶段终审和结算检查已通过 |
| 已取消 | 尚未开始时取消，历史保留 |

大脑完成当前目标后执行 `finish-goal --goal <goalId> --summary <验收摘要>`，随后实际 `resume`。服务自动处理下一个已授权目标；队列为空时保留成员待命，之后新增目标仍可使用这些会话。「结束整个项目」是独立操作，有未完成目标时拒绝执行，待开始目标也需要完成或取消。任务页可按所属目标筛选。服务重启保留队列、开始授权、活动目标及规划编号；初审端仍按原有规则恢复续接，不伪造在线证据。

旧单目标项目升级时只补充目标归属，不改写目标内容、绑定、快照或冻结契约；旧的等待启动项目仍需明确开始，不会被自动授权。重置历史任务仅允许同一目标且没有另一个活动目标；原证据存入重置审计，恢复该目标并暂停项目，核对后再继续。

创建接口仍为 `POST /catalog/api/projects`，请求保留可选 `startMode: "auto" | "manual"`（默认 manual；旧 auto 参数也仅保存，不再提前授权）、`workers`（省略使用默认团队），响应增加 `goalId`。已有目录追加目标。项目管理命令支持 `start-goal`、`cancel-goal` 和 `configure-team`，沿用会话、CSRF、状态版本与命令收据保护。

服务数据和凭据仍位于选定项目的 `.task-dispatch/runtime/`；主页索引只保存路径。新增功能需要重新启动统一控制台及相关项目服务后生效。

[目标队列与成员面板预览（隔离演示）](images/web-task-members.png)

接入效率同时记录操作次数和实际耗时：默认三名成员各执行一次 connect，可并行；自动模式不需要额外点击开始。自动测试仅覆盖模拟宿主，耗时受本机进程与测试并发影响；真实平台响应时间尚未验证，不承诺固定秒数。

## 状态怎么看

| 显示 | 含义 |
| --- | --- |
| 已绑定端 | 服务保存了身份，不代表客户端持续在线 |
| 最近有通信 | 此绑定在最近 60 秒发送了有效认证请求 |
| 未知 | 没有足够新鲜的通信证据，不等于离线 |
| 已 armed | 端已申请挂起，仍须核实宿主监听和实际投递 |
| Qoder 监听有效 | 描述文件中存在未过期、进程仍存活的监听租约 |
| 已送达 | 适配器确认投递；Qoder 是 Hook 已消费通知 |
| 已领取 | 端实际调用 claim，任务归属已确定 |
| 领取停滞 | 初次通知和一次受控补提醒都已送达，但端仍未 claim，需要人工核实或恢复 |
| 已由后续任务解决 | 原任务没有通过，但大脑已把它关联到一个已通过的替代任务；这是可审计终态，不再计入未完成或异常 |
| 数据已过期 | 管理台与服务断开，界面保留最后快照 |

选择项目可查看该项目连接与任务；选择连接或任务会同步筛选事件。Qoder 详情包括最近 Hook、描述文件更新时间、监听到期和通知消费时间。其他宿主仅探测已绑定会话，不扫描和选择陌生会话。宿主观测默认约 10 秒一次，同时最多 4 个探测；慢宿主会延后下一次探测，页面会标明过期。

快照每 2 秒推送；事件实时推送。事件流支持搜索、平台/等级/项目/绑定/任务筛选、暂停显示和历史分页。记录来源包括已提交业务事件、状态变化、客户端请求摘要、宿主观测及管理操作；不记录完整对话、模型思考或未上报的工具调用。

## 控制与排障

项目主页直接提供暂停/继续、结束/重开；异常任务卡片按状态提供重试、追加尝试次数、改派执行员和再次提醒。简单操作点击即提交；需要参数或涉及删除、重置等操作时才打开精简面板，成功后自动关闭。改绑只选择交接方式；存储清理自动展示待清理目录与可释放空间，点击一次即可执行预览中的清理。所有提交保留状态版本与命令收据保护；后台控制下拉菜单仅保留归档项目、恢复归档项目和永久删除项目。

![精简后的追加额度弹窗，仅保留追加次数](images/simplified-command-dialog.jpg)

阻塞会形成大脑待办。大脑使用自己的会话凭据执行重试、改派、修复授权、候选协调或计划修订；管理台用于观察证据和人工管理，不要求大脑借用管理员令牌。若计划变化需要改变已经开始的任务契约，应登记新任务并显式填写 `supersedes`，而不是原地改写审核目标。新任务通过后旧阻塞显示“已由后续任务解决”；在“所有任务”中仍可查看原失败和替代依据。

“生成改绑提示词”按接收端平台分别输出：一条 30 分钟邀请同时给出 Codex、MiMo、Qoder、OpenCode（worker 另有等待型平台）和“由接收端确认平台”各一份完整提示词，弹窗顶部下拉切换，复制到的就是当前所选平台那份。默认选中的平台取自被替换绑定已记录的 provider，判定不了时默认“由接收端确认平台”。MiMo、OpenCode 变体的命令已带 `--session-id <当前真实会话 ID>`，需接收端填入宿主显示的当前真实会话 ID；Codex 变体省略该参数（显式 `--provider codex` 后客户端自行读取 CODEX_THREAD_ID）；Qoder 变体只需本邀请的一次性 `--invitation-id`。切换平台不重新生成邀请，有效期与所有权结算规则不变；平台仍由接收端确认，管理台不代为猜测。

- 暂停停止后续调度，当前回合继续。
- `uncertain` 重试前要核实旧执行已停止；送达不确定的唤醒不能从页面强制重复发送，应在原会话核实并 claim/park。
- 通知 `sent` 后超过领取宽限期，服务最多自动发送一次带独立标识的补提醒；继续未领取则显示“领取停滞”，不循环重发。管理员点击“再次提醒”即可提交，该操作只为当前未领取 attempt 补充一次待命授权，不会标记为已领取。
- 解绑在途执行员会被拒绝；解绑审核端复用现有审核恢复逻辑。
- 操作提交使用打开面板时的状态版本；状态变化后需重新打开面板核对，不自动改用新绑定。
- 重复命令使用持久化收据返回已有结果；若服务在操作中崩溃，旧命令标记为结果不确定，不盲目重做。结果不明时页面再次提交复用同一命令 ID。
- 清理只执行指定预览，预览变化会被拒绝。停止服务会断开页面，重启需运行本地启动器。

错误提示包含服务实际报告的证据。已领取 5 分钟无进度仅作排障提示，不自动撤销任务所有权。连接拓扑按“大脑—初审端—调度服务—执行员”展示，初审端不再与 worker 混排。事件记录故障会显示在健康提示中，不阻止业务任务执行。

## 项目归档、删除与任务完全重置

归档、恢复归档和删除从“后台控制”选择，重置从任务详情进入；面板自动加载影响范围，核对后点击操作按钮即可，无需额外预览：

- **归档项目**：默认隐藏并暂停，保留任务和连接记录；存在在途/待核实任务时拒绝归档。勾选总览的“显示已归档项目”可查看，使用“恢复归档项目”恢复；恢复后保持暂停，需要手动继续。
- **永久删除项目**：核对项目与影响范围后点击一次确认，撤销全部连接并移除调度记录。不删除源工程和磁盘产物，保留审计和最小删除标记；没有一键恢复。旧凭据无法提交，旧客户端也不能自动重新创建已删除工作区。确需重新注册时，通过管理 CLI 的 `add-project` 配置显式指定 `recreateDeleted:true`，再由新会话接入。
- **完全重置任务**：自动列出选中任务、下游及同阶段任务，点击一次确认；清空执行、审核、唤醒、重试次数、会话缓存及产物关联，回到待执行，任务额度恢复默认 30。保留当前任务定义，分派恢复计划中的执行员；旧记录保存到服务目录 `task-resets/<resetId>.json` 仅用于审计，不参与恢复执行。项目暂停，所有唤醒端解除 armed，核对后再继续并重新 park。
- **下游任务**：页面重置会一并处理预览中的全部下游及同阶段任务，无需额外勾选。无关任务保留。旧 attemptId 提交将失败，不会覆盖新任务。
- 有在途/待核实任务时，删除或重置要求确认相关宿主执行已经停止；服务内部仍在处理该项目时始终拒绝。页面按钮会明确提示先停止相关执行，点击该按钮即确认；操作原因由控制台自动记录。

重置不回滚工作区文件，也不清零项目历史累计次数或其他任务的额度。对于完成项目中的任务，重置会清除项目完成标记，并撤销相关收尾覆盖记录。

## 日志与导出

事件位于服务数据目录 `monitor/events.jsonl` 及轮转分段，每段最多约 4 MiB，最多 8 段。内存保留最近 1000 条供快速重连补发；更早历史分页从磁盘读取。超出快缓存或跨服务重启时，前端重拉快照和历史。

服务启动、停止事件和后台 `service.log` 记录 ISO 时间、运行版本、Node 版本、实例 ID、PID；启动记录另含监听端口和数据目录。管理台服务详情展示版本、PID、实例与启动时间，便于把一次试跑准确对应到实际加载的进程。任务详情逐次展示完整计量、时间窗口计量或不可用原因，未知消耗不会显示为零。

业务仍以 `state.json` 为准；日志不是调度数据库。高频 heartbeat/status/wait 请求按每绑定每分钟摘要合并。启动时可补录业务日志游标之后仍保留的业务事件；崩溃前未持久化的通信观测无法恢复，旧业务状态没有记录过的过程不会伪造。

诊断包包含当前筛选的项目快照和最多 100 条匹配事件（API 上限 200），不包含凭据字段与对话正文。保留工作区路径、会话 ID 和错误摘要；对外分享前仍应核对是否涉及业务信息。任意自由文本中的未知密钥格式不能保证全部识别，应避免在进度摘要中上报密钥。

管理命令收据位于 `monitor/commands.json`，最多保留约 2000 条已完成操作；未决收据不自动淘汰。

## 2026-09-22：证据与存储诊断补充

新增桌面 `preflight --task ... --attempt ...` 只读命令，返回范围与输入差异；提交回执保存完整 reviewChanges。使用方法见 `docs/review-validation.md`，本轮未新增管理台按钮。

配置 `evidenceResult` 的自动检查失败会显示 `blockKind:evidence`，在放行给模型审核前停止；查看该 attempt 的 validation report，而不是重新运行真实模型生成数据。

发生回执存储恢复时，使用桌面 `status` 查看 `storageRecovery`。该字段表示服务内存中的恢复暂停，可能尚未写入任务状态；管理台原任务仍可能显示 running/reviewing。不要因此改派或重启 worker。先查错误码及是否 exhausted，再解决存储问题；流程与重启边界见 `docs/storage-usage.md`。本轮不新增管理台自动处置或重启行为。

## 返工、用量与批次面板（未发布）

项目页新增“返工、用量与批次”：准备/领取/结算分别展示，累计返修来自历史事件；初审放行后退回显示有效候选分母与任务数。历史缺失、计量未知、冲突与窗口外增量均明确标示，完整上报与窗口观测不相加，不展示未经验证的费用节省。

规划、排障与其他活动列出来源、结束状态和可查 token。批次列出固定成员、等待原因、候选摘要、共享审核领取情况和分项结论。“等待批次终审”仍是未完成任务；共享在途审核出现在大脑连接上，阻塞或通知停滞进入告警。开启、登记、取消及回执使用已认证的大脑 CLI，详见 review-validation.md。


## 任务全景与阶段终审

任务页顶部始终显示全部任务数、已验收数、待大脑终审数、异常数和整体完成进度。任务页签数量也使用全部任务数；搜索、阶段和状态筛选只改变匹配范围，不改变总数。已由后续任务解决的任务单列说明，并计入整体终结进度。

阶段区展示每个阶段最新轮次、累计任务、本轮成员及大脑整体结论。补修轮的审核范围包含原任务；任务卡片区分尚未登记阶段、需要阶段终审、等待补修后复审、终审准备/领取/审核、终审受阻和已通过。详情保留参与过的终审轮次。

默认依赖图按前置关系分层，用箭头连接前置与后续任务；同层无前后依赖，可用于并行规划，实际项目调度仍串行。选中任务高亮直接前置与后续关系，点击“查看审核详情”查看阶段及审核历史。图中筛选淡化未匹配节点以保留关系上下文；任务列表仅展示匹配项，前置/后续编号可点击跳转。依赖循环、缺失前置及受影响任务单独提示，不能被误看成可执行的独立任务。

可用 `node scripts/task-board-preview.cjs` 启动只读演示，终端会输出独立 localhost 地址。预览使用演示数据与正式前端资源，不连接真实调度或模型。正式控制台需重新启动加载新增的模块资源路由。
