# Web 返工、用量与批次摘要 — 技术方案

## 1. 需求概述

- **功能目标**：缩小概览中“返工、用量与批次”默认占用的空间，同时保留完整明细。
- **验收标准**：默认只显示紧凑摘要；鼠标或键盘可展开明细；轮询刷新和同项目重绘保持展开状态；统一控制台与直连管理台一致。
- **需求来源/提出人**：用户于 2026-09-24 提出。

## 2. 影响面分析

| 涉及项 | 类型 | 影响说明 |
|--------|------|----------|
| `runtime/console-web/app.js` | 统一控制台界面 | 将原有指标、活动与批次明细置于折叠容器 |
| `runtime/console-web/style.css` | 统一控制台样式 | 设置紧凑摘要、展开状态和小屏样式 |
| `runtime/web/app.js` | 直连管理台界面 | 保持与统一控制台相同的展示规则 |
| `runtime/web/style.css` | 直连管理台样式 | 对应折叠组件外观 |

## 3. 边界与异常场景

| 场景 | 预期行为 |
|------|----------|
| 项目尚无统计数据 | 摘要提示暂无数据；明细显示原有空状态 |
| 用量未知 | 显示未知，不按 0 汇总 |
| 批次关闭或无批次 | 摘要显示关闭或无进行中批次 |
| 轮询刷新 | 维持用户当前展开或收起的选择 |
| 切换项目 | 新项目默认收起，返回已看项目时可恢复该项目状态 |
| 小屏和键盘操作 | 摘要可换行，原生 `summary` 保持键盘可操作 |

## 4. 技术方案

- **选定方案**：用户以“继续”确认推荐方案 C1，使用紧凑摘要和原生 `details/summary` 折叠明细。
- **被否决方案**：独立页签增加导航与发现成本；完整展开继续占用概览空间。

### 关键设计

- 摘要只展示与操作判断相关的返修、计量覆盖、批次状态；原有指标和说明仍保留在展开区域。
- 使用原生 `details/summary` 折叠语义，避免自建按钮与可访问性状态同步。
- 按项目键记录 `open`，同项目重绘保留原容器，跨项目时恢复已保存的状态。
- 仅设置 `textContent`，不将统计字段作为 HTML 注入。

## 5. 实现流程

1. 接收项目快照并计算紧凑摘要。
2. 创建默认收起的 `details` 容器，将现有明细节点附加到容器中。
3. 当用户切换展开状态时，将对应项目状态保存到内存映射。
4. 刷新或重绘时恢复对应状态并更新数据；详细活动和批次仍沿用原有字段。
