# 任务总结 — 大脑唤醒平台匹配

- **任务类型**：修复
- **任务分级**：标准档
- **关联文档**：无

## 1. 任务内容

修复角色连接时平台来源不明确、可能导致唤醒绑定不匹配的问题，并确保大脑连接后明确交付其他角色的连接提示。改动覆盖桌面客户端、Skill 接入说明及连接/续接/多人协作回归测试。

## 2. 方案与选择

- **候选方案**：方案 1（客户端强约束并在现行 Hook 能力范围内辅助检查，推荐并已选）；方案 2（分别开发平台 Hook）；方案 3（仅修改提示词）。
- **选择理由**：CLI 能在所有平台统一阻断错误参数，角色邀请和 brain 回执能约束模型行为；各宿主 Hook 能力不统一，单靠 Hook 无法覆盖 Codex、MiMo、Qoder、CodeArts，也不应复活已退役的 Qoder Stop Hook。

## 3. 根因分析

1. `connect/rebind` 客户端已经拒绝缺失或 `auto` 的 provider，因此服务端不会静默猜测平台；但角色邀请只要求接收端填写 `<当前真实平台>`，没有要求接收端先向用户确认，模型仍可能自行猜测或遗漏。
2. 大脑首次连接回执始终包含 reviewer 邀请，但在 staffing 尚未登记时，`workerInvites` 按现有实现和测试约定为空；执行 `staff` 后才生成具名 worker 邀请，因此首次连接不会直接给出完整的其他角色连接提示。
3. 各宿主 Hook 能力不统一：Qoder 现行实现使用 App Plugin 且已退役旧 Stop Hook；CodeArts Hook 用于会话发现和消息桥接；MiMo 支持取消会话回合但项目尚未安装平台选择检查；Codex 没有同构的项目级提示拦截 Hook。因此不能仅依赖一套 Hook 在所有平台统一阻断。

实施后，每个角色邀请均要求接收端先询问用户选择真实平台；缺失或 `auto` provider 会在服务和凭据产生副作用前失败。brain 回执在 reviewer、staffing 或计划内 worker 尚未就绪时标记 `peerSetupRequired`，正常待命回执提升为 `setup-peers`，同时给出 reviewer 邀请、worker 邀请状态和必须执行的下一步。若唤醒配置本身失败，原有 `attention` 保持更高优先级。
