# 任务总结 — MiMo 唤醒后未领取任务

- **任务类型**：修复
- **任务分级**：轻量档
- **关联文档**：`docs/plans/2026-09-14-MiMo唤醒后未领取任务.md`

## 1. 任务内容

修复 MiMo 收到 planning 唤醒后可能只展示 `claim` 命令、未实际领取待办便结束回合的问题。改动位于共享唤醒核心，因此同时适用于 Codex、MiMo 和 CodeArts 的通知内容。

## 2. 方案与选择

- **方案 A**：仅强化唤醒提示。
- **方案 B（用户选定、推荐）**：强化提示，并对长时间未领取的 planning 增加看门狗。
- **选择理由**：既降低模型只复述命令的概率，又能对通知送达后的失联状态给出可观测标记，无需引入高风险 stop 或自动重发。

## 3. 根因分析

原唤醒通知仅要求“执行 claim”，没有明确要求调用终端工具，也没有禁止将命令当作最终文本输出。MiMo 因此可以在复述命令后结束回合。同时，planning 通知一旦标记 `sent` 就不再检查是否实际领取，使待办可以无声滞留。

修复后，普通任务、planning 和 scope 通知都要求实际调用终端，原样复用现有路径，禁止仅展示命令。planning 通知送达超过 60 秒、brain 仍未取消 `armed`、目标会话已空闲时，复用现有 `needsAttention` 和 `planning_stalled` 机制提示人工处理。
