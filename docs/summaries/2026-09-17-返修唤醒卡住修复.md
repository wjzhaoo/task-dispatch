# 任务总结 — 返修唤醒卡住修复

- **任务类型**：修复
- **任务分级**：标准档
- **关联文档**：`docs/specs/返修唤醒与管理台异常处置.md`

## 1. 任务内容

修复审核退回后 worker attempt 已创建但未被会话领取的停滞链路，增加一次自动补提醒、最终停滞告警和管理员再次提醒能力。

## 2. 方案与选择

- **候选方案**：A 仅人工重试；B 受控自动补提醒 + 告警 + 人工恢复（用户选择、推荐）；C 把送达视为领取（否决）。
- **选择理由**：既能主动推进，又不伪造 claim，不对 uncertain 投递盲目重发。

## 3. 根因分析（修复类任务必填）

第一处根因是 `runtime/core/wake.cjs` 在 `wakeNotice.status === sent` 后直接跳过该 attempt，没有判断目标角色是否实际 `claim`；管理端 `wake-retry` 又只允许 `pending`，因此 sent-but-unclaimed 没有自动治理或人工恢复入口。真实试跑进一步暴露第二处根因：宿主 `read()` Promise 可以在底层响应异常时永久不返回，而 wake 与 monitor 没有外层硬超时，导致 `Wake.busy` 和 probe `inFlight` 长期占用；后续 attempt 连 `sending` 都无法进入。
