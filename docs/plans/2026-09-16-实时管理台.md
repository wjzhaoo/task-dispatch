# 实时管理台实施计划

## 1. 目标与范围

为现有 task-dispatch 单服务增加中文 Web 管理台，跨项目观察 Codex、MiMo、Qoder 等端的连接、调度、唤醒、领取、执行、提交、审核和收尾，并提供受控的后台操作。本次用户要求制定计划，本文不代表已经实施。

Qoder 安装与原会话唤醒是明确保留的能力。管理台需要呈现它的 Hook、监听租约、通知消费及后续领取状态。

默认本机访问，使用现有服务和数据目录。首期不增加远程部署、多用户权限系统、模型聊天工具或新的调度引擎。不承诺获取宿主未提供的模型思考、完整对话或工具调用；展示服务实际观察到的交互和客户端上报的进度。

## 2. 已核实的现状

- `runtime/wizard.cjs` 提供命令行看板、项目暂停/恢复、重试、额度、存储等操作，无 Web 前端。
- `runtime/server.cjs` 监听 127.0.0.1，提供 `/status`、`/command`、`/desktop`，目前拒绝带 Origin 的请求；管理接口使用本地 admin-token。
- `runtime/core/storage.cjs` 维护 revision 和 events，写入时整体保存 state.json；不适合将每次心跳和探测都追加到业务状态。
- `runtime/core/desktop.cjs` 的 connections 提供绑定、sessionId、provider、wakeEnabled、armed，但不足以说明真实在线与否。
- `runtime/core/wake.cjs` 保存部分 wakeNotice 和进度，部分失败仅被捕获或覆盖，不能还原完整时间线。
- `/desktop` 的 heartbeat 返回成功；未见统一的端在线时间记录。Qoder 的描述文件、监听租约与消费记录在适配器中，尚无管理台投影。

## 3. 页面设计

| 页面 | 主要内容 | 解决的问题 |
| --- | --- | --- |
| 全局总览 | 服务状态、项目概况、待处理异常、各端连接表、最近交互 | 现在谁在工作、哪里停住了 |
| 项目详情 | brain → 服务 → workers/reviewer 连接图、任务阶段、当前所有者、等待原因 | 哪个端应该接下一步 |
| 连接详情 | 平台、角色、工作区、绑定代次、会话、观测时间、宿主状态、监听状态、最近错误 | 已连接为什么收不到任务 |
| 任务追踪 | 按 attempt 展示派发→唤醒→领取→进度→提交→初审→终审→收尾 | 到底断在哪一步 |
| 事件中心 | 实时事件、历史分页、按项目/端/任务/等级/关联 ID 筛选 | 还原故障发生过程 |
| 控制与诊断 | 可用操作、参数、执行结果、操作审计、诊断包导出 | 从发现问题到处理问题 |

桌面布局：左侧项目导航，顶部服务与实时连接状态，中间连接图和任务列表，右侧所选对象详情，底部可展开事件流。全局与项目过滤联动；历史浏览时可暂停自动滚动，显示新增事件数量。

## 4. 状态模型：展示事实和时间

连接状态拆为四个维度，不用单一在线布尔值：

1. 身份：已绑定、已解绑、已被新会话替换；包含绑定代次，避免旧响应污染新连接。
2. 通信：最后有效请求、最后成功探测、最后失败及证据来源；显示正常、过期、不可达或未知。
3. 工作：空闲、待领取、执行中、审核中、等待收尾、阻塞；来自业务状态。
4. 唤醒：未配置、已配置未 park、已 armed、监听可用、监听过期、发送中、已确认送达、送达不确定；按平台能力显示。

Qoder 单独显示最近 Hook 事件、监听开始/到期、租约有效性、通知发布和消费时间。Hook 已消费不等于模型已执行；只有 claim 才表示任务被领取。armed 不等于存在有效监听器。

休眠端没有持续心跳时显示最近观测和未知状态；不因为心跳超时自动解绑或接管审核。前端自身与服务断开时标明“数据已过期”和最后更新时间。

## 5. 实时与事件设计

推荐同一 Node 服务托管静态页面及管理 API，使用 SSE（服务向浏览器推送事件）配合普通 HTTP 控制请求。前端优先采用无构建依赖的 ES modules、HTML/CSS，延续现有无 npm 依赖结构；用 SVG 表现角色连接，任务链路以时间线展示。

- 首次读取脱敏快照，随后订阅增量事件。快照包含 revision、事件游标、服务实例 ID 和 observedAt。
- 保证快照与订阅之间无空窗：按游标补发；游标超出保留范围或服务实例变化时明确要求重新拉取快照。
- SSE 自动重连、心跳保活、有界缓存和慢客户端断开；断流提示，可降级为低频快照刷新。
- 事件字段：eventId、sequence、服务实例、时间、类型、等级、projectId、bindingId/代次、provider、role、workerId、taskId、attemptId、correlationId、阶段、结果、耗时、脱敏摘要。
- 覆盖接入/换绑/解绑、有效请求、park/wait、唤醒探测与投递结果、claim/progress/submit、审核与收尾、控制命令和异常。
- 高频通信观测在内存合并，只保存状态变化和周期摘要；禁止每秒整体写入 state.json。
- 使用单服务写入的独立追加事件日志，按容量/日期轮转，提供分页与明确保留策略。Qoder Hook 由服务读取观测并按标识去重，避免多个进程竞争同一日志。
- 业务事件随业务提交产生，发布失败可根据已提交 revision 补齐；诊断日志写入失败要在健康状态中显示，不能阻塞原有任务执行，也不能声称历史完整。
- 历史记录从升级部署后开始；旧状态只能作为快照，不倒推或伪造之前的事件。

## 6. 管理 API 与控制

新增 `/admin/api/overview`、`projects/:id`、`connections/:id`、`tasks/:id`、`events`、`stream`、`commands`，具体路径在契约阶段统一。API 返回专用脱敏投影，不直接把 `/status` 全量业务状态交给页面。

首期控制接入已有业务能力：暂停/恢复项目、重试阻塞任务、追加尝试额度、结束/重新打开项目、存储清理预览与执行、停止服务。界面明确暂停仅停止后续调度，停止服务可能使执行结果需要核实。

换绑/解绑、改派、重试唤醒作为第二批控制：先补 operator 权限入口，复用现有绑定、所有权和投递检查。禁止前端冒用角色凭据，禁止绕过送达不确定保护直接重复唤醒。只读诊断不发送模型消息；重新 park 需要宿主执行时，显示实际所需动作。

所有写操作有 commandId、参数校验、目标 revision/绑定代次检查和审计。重复点击不重复执行；冲突时刷新目标。区分“请求已接收”和“操作已完成”，记录前后状态、结果和失败原因。删除清理、停止服务、终止绑定等操作显示具体影响并确认。

## 7. 本机浏览器接入

- 保持监听回环地址，校验 Host 与同源 Origin；仅开放专用管理路由的浏览器访问，保留桌面接口边界。
- 本地启动器生成一次性短时登录票据，交换为 HttpOnly、SameSite 会话 cookie；长期 admin-token 不进入页面、URL或浏览器存储。票据不得写入访问日志，交换后清除临时地址信息。
- 修改请求检查同源与 CSRF 凭据；限制静态资源路径，设置 CSP；事件文本按纯文本渲染。
- 展示与导出采用字段白名单，过滤 token、credential、密钥和未授权对话正文。可按需展开脱敏请求/响应摘要。
- 服务停止后页面保留最后快照并说明断开。首期重新启动走本地启动器；不假装已停止的服务还能响应“启动”按钮。独立常驻进程管理器不在首期范围。

## 8. 故障定位规则

优先给出可核验的阻塞原因和证据链接：无匹配 worker、项目暂停、启动门禁未完成、额度耗尽、端未 park、Qoder 监听过期、宿主不可达、通知送达不确定、已送达未领取、已领取无后续进度、审核等待、收尾未处理。

每条提示包含最近事实、持续时长、证据事件和建议动作。时间阈值是告警阈值，不直接判定模型死亡，不自动改变任务归属。

## 9. 分批实施

| 批次 | 交付 | 主要范围 | 验收 |
| --- | --- | --- | --- |
| P1 观测契约 | 状态投影、事件字段、关联 ID、平台观测接口 | server、storage、desktop、wake、平台适配器，新增观测模块 | 模拟三端能准确区分绑定/监听/送达/领取；不改变调度结果 |
| P2 实时只读管理台 | 总览、连接详情、任务时间线、事件筛选、浏览器登录与 SSE | 新增管理路由和静态前端、启动入口 | 多项目隔离、断线恢复无丢失窗口、状态过期明确可见 |
| P3 后台控制 | 已有控制操作、幂等、冲突检测、审计 | 管理命令层与既有业务方法 | 重复点击只执行一次，过期目标拒绝，执行结果可追踪 |
| P4 排障与平台深化 | Qoder Hook 详情、告警、诊断包、受控解绑/改派/唤醒恢复 | 观测适配器、诊断与控制扩展 | 能定位监听过期和通知未领取；不能误发或重复执行 |
| P5 联调交付 | 自动化、真实三端验收、使用与排障文档 | tests、scripts、docs、启动入口 | 完整链路可回看，已有 npm test 和 verify:skill 无回归 |

先交付 P1+P2 供实际观察，再接 P3+P4；避免到最后才验证状态是否可信。预估工作量需在 P1 契约和真实平台可观测性确认后细化。

## 10. 验证标准

- 注入“未 park、监听过期、宿主不可达、通知已消费但未 claim、断开、换绑、审核等待”场景，界面原因与证据一致。
- 跑完整执行→初审→终审→收尾，按同一任务及 attempt 查看各阶段和端间交互。
- 模拟 SSE 断线、服务重启、历史游标过期与慢客户端；有补发或明确快照重置，不静默遗漏。
- 自动化覆盖越权请求、外部 Origin、CSRF、字段脱敏、命令重复与 revision 冲突。
- 隔离环境使用至少 20 个项目、100 个绑定、累计 10 万条事件验证分页、有界缓存和日志轮转；目标为本机事件通常 2 秒内可见，具体性能记录环境与测量值。
- 所有夹具和测试数据放项目 `tmp/admin-console/`。真实 Codex/MiMo/Qoder 联调单列结果，未完成不得标记通过。
- README 和管理台说明写清启动方式、数据来源、状态含义、控制影响和历史保留。旧命令行控制台继续可用，新增 Web 启动入口避免破坏既有脚本调用。

## 12. 实施补充决策

- 用户指定使用冷门端口，Web 启动入口默认 43187；用户授权现在重启主服务，已执行并保留原任务与连接状态。
- 用户要求模型联调使用低思考强度。本次隔离联调不调用模型；后续真实模型回合必须使用平台明确支持的低档，不猜测参数。
- 前端复用统一 overview 投影选择项目、连接与任务；独立详情路由暂不重复实现相同数据。
- 为保护真实会话身份，换绑由宿主 connect/rebind 完成，管理台提供观测和受保护解绑；不生成虚假的宿主会话。
- 任务列表默认显示未完成任务，可切换查看全部；窄屏支持项目筛选。
- 事件保留按容量轮转（最多 8 × 4 MiB）；保留期不足时明确重建快照。操作收据独立持久化。
