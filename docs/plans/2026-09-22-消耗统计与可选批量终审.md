## 3. 方案与关键决策

### 3.1 统计口径

- attempt 是调度尝试，不等于模型调用。分别展示准备、领取、结算数量；自动校验失败但未被模型领取的审核不能算已发生模型审核。
- 从事件及回执身份计算累计返修，不改变 repairs 的现有执行控制含义。按事件 ID 去重；历史事件缺失时报告覆盖不完整，不根据最终状态猜历史。
- “业务返修”统计已记录的 needs_fix，按 worker/reviewer/brain 阶段关联；“越界退回”来自 scope_returned；“基础设施异常/恢复”仅依据结构化错误码和明确事件。无原因的旧 operator_retry 归未分类，不能一律算基础设施故障。
- “初审通过后终审退回”必须匹配同一 taskId＋artifactId，并确认先有 reviewer pass，再有 brain needs_fix。展示分子、有效匹配样本数及任务数，避免把每次回执当独立任务。
- 缓存输入包含于输入、推理输出包含于输出；显示已知用量、未知项和覆盖范围，不换算订阅额度、不编造价格或节省百分比。

### 3.2 大脑活动与用量归属

- 增加项目级 brain 活动记录，类型为 planning、troubleshooting、other；使用真实绑定、活动 ID、开始/结束时间和来源，不能让模型估计 token。
- 规划领取/closeout、明确的异常处置领取/确认自动建立或结束活动；首次规划及窗口外沟通支持显式 activity-start/activity-end 或真实平台计量导入。尚未记录的阶段保持未覆盖，不称为完整账单。
- Token 增量按源会话和计量事件唯一标识去重。互相重叠的审核、规划、排障时间窗不重复计费；无法唯一归属的增量单列 unallocated/conflicting，保留候选归属，不任意指定优先级。
- 已有平台上报的完整计量优先于该记录的观测值，但不能把同一范围的窗口值再相加；跨记录是否重叠无法核实时展示分项且总计不完整。活动耗时不是推理耗时。

### 3.3 批量终审的安全边界

- 默认关闭；首版仅支持 desktop 模式，由 brain 明确登记里程碑、固定任务成员及独立性说明。不开新模型、不按固定“每批几项”凑数。
- 每项明确 risk=low、共享接口未改变、完整允许路径和读取依赖；核心接口、权限/支付/迁移/联机一致性、存在未明确风险的任务不允许入组。程序检查声明与结构约束，但不声称能自动理解全部业务风险。
- 成员之间无传递依赖，允许写路径互不重叠，且不得写其他成员声明的读取依赖；组外前置依赖必须已通过。任务定义在开始前冻结，实际修改超出契约仍走原范围门禁。
- worker 和 reviewer 保持逐项执行、逐项初审；通过初审的成员保留未 accepted 状态和批次等待标记。仅允许推进该固定批次内下一独立成员，组外依赖继续等待。
- 入组要求配置可执行验证和 evidenceResult，且检查通过；仅静态文档声明、不具备自动证据检查或没有在线初审员的任务不进入批次。无法满足时返回明确原因，按原逐项路径处理，不能静默放宽。
- 开始执行时冻结公共基线；最终审核冻结复合候选、每成员原候选/变更/契约摘要和初审证据。验证复合候选相对公共基线仅有所有成员已授权增量（控制文件漂移仅沿用已有规则），每成员交付路径未被后续成员改变。
- 普通单项审核的全候选一致性检查保持不变。批次使用独立审核目录和专用复合候选校验，不能简单忽略“其他文件变化”绕过旧检查。
- 批次正式审核期间整个项目禁止新执行；一份审核领取、一份回执，每项必须给出 pass/needs_fix/blocked。身份或成员缺失、重复、候选过期时整份回执不生效；合法混合结论在一次持久提交中逐项生效，不伪造统一通过。
- 首版返修项退回原单项执行/初审/终审链，不自动重新拼批；已通过成员正常 accepted。所有分项判定完成后生成一次阶段收尾。
- 成员执行阻塞、初审员断开或没有可推进成员时，批次产生明确异常待办，不长期静默等待，也不把尚未通过的成员算完成。只有未领取的批次可由 brain 显式取消并回到单项；已领取批次沿用确认停止及交接保护。
