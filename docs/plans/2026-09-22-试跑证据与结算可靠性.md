- novel2comic 本轮于北京时间 2026-09-22 03:06 完成：12 项任务记录，8 项 accepted、4 项由后续任务替代解决；35 次 worker、24 次 reviewer、17 次 brain attempt。

- 可观察目标：配置的证据校验在模型审核前发现机械错误；审核输入变化报告具体路径；提交前可以只读检查范围；瞬时存储失败不会直接产生新审核 attempt。

## 2. 现状锚点（执行者必读）

| 位置 | 现状 | 作用 |
| --- | --- | --- |
| `runtime/core/storage.cjs` atomic、Store.change | 临时文件写入并 fsync 后单次 renameSync；成功落盘才更新内存 | 存储恢复基础 |
| `runtime/core/dispatcher.cjs` settle、recover | 回执结算异常统一 block；恢复可读取持久回执 | 避免重新调用模型 |

| `runtime/core/snapshot.cjs` manifest、difference、allowed | 已过滤根部 IDE 点目录；嵌套缓存不自动全部过滤 | 复用范围判定，不放宽保护 |

| `docs/review-validation.md` | 当前自动验证仅支持带锁文件的 npm 项目 | 兼容边界必须保留 |
| `PROJECT.md` | 构建目录为根目录 `.` | 在根目录验证 |

## 3. 方案与关键决策

- 复用现有独立验证树和管理员配置的检查命令，增加结构化证据检查结果及示例；不把小说领域字段硬编码进调度器。
- 领域适配器负责从 raw/ledger 生成、核对报告，声明各类事实来源。服务负责将结果绑定候选并执行门禁。没有配置的检查明确显示未配置，不能显示通过。
- 只读预检提前报告问题，但最终提交仍重新核验，避免预检到提交间发生变化。
- 测试在验证副本运行，审核副本只用于阅读；改变候选源文件仍应失败，不能把真实数据或整个证据目录加入忽略清单。
- 存储恢复先重试原子替换；若回执已持久化，则恢复同一 attempt 的结算。只有明确可重试的存储错误适用，不把业务错误自动放行。
- 不减少终审、不新增角色、不调整模型、不修改返修预算。本期先消除可机械处理的浪费。

## 4. 任务清单

### T1 复用验证环境增加证据一致性门禁与示例

- 文件：`runtime/core/validation.cjs`、`tests/validation.test.cjs`，新增 `examples/evidence-validation/` 中的 Node 校验器、脱敏夹具和说明。
- 改动：在现有配置中增加可选结构化结果文件路径；必须位于声明的 outputs 下且为项目相对路径。结果包含版本、检查 ID、passed、错误定位；服务自行绑定 artifactId/artifactHash，不信任脚本自行声明候选身份。配置该结果时，文件缺失、结构错误、任一检查失败或命令非零退出均不能通过。未配置时保留旧行为。
- 示例：以虚构 raw、全局 ledger、匿名材料、report 演示按场景分组核对调用索引、状态和数量、已有材料完整性；报告生成和核验使用明确来源，不用模型重新手填统计。示例不得读取真实配置或发起外部调用。
- 验收：错误总数、重复/遗漏调用索引、状态冲突、遗漏匿名材料分别失败；一致夹具通过；结果文件缺失、路径逃逸和非法结构失败；旧配置仍通过原测试。
- 结果：已增加 evidenceResult 协议与候选绑定，失败在模型领取前阻塞；脱敏示例和错误夹具已通过定向测试，旧配置兼容。
- 状态：[x] 已完成

### T2 增加只读预检与审核变更诊断

- 文件：`runtime/core/desktop.cjs`、`runtime/desktop-client.cjs`、`runtime/server.cjs`、`runtime/core/snapshot.cjs`、`runtime/core/validation.cjs`，相关 `tests/desktop.test.cjs`、`tests/validation.test.cjs`、`tests/scope-recovery.test.cjs`。
- 改动：增加领取者可调用的 preflight，只针对当前身份拥有的 attempt。worker 比较当前文件与已有基线，报告允许范围外路径及 Windows 保留文件名；reviewer 比较审核树与交付 manifest，报告新增、修改、删除路径。复用现有哈希和范围函数；不创建候选、不写回执、不结算、不消耗 attempt。
- 改动：提交回执兼容保留 reviewChanged，并增加具体变更列表；验证环境变更错误也列出路径。输出限长但持久诊断保留完整列表，避免复制文件内容或敏感信息。
- 隔离：继续使用已有 validations 树；明确审核员应阅读验证证据，不能在审核输入树运行会写文件的检查。验证临时目录在启动检查前创建；用测试证明验证产物不修改 workspace/artifact/review 树。不能宣称此目录隔离等同 OS 安全沙箱。
- 验收：预检不改变 revision、事件或 attempts；越权身份被拒；通过预检后再越界仍被 submit 拒绝；源文件、真实数据和证据变化不被忽略；具体路径可定位；旧布尔回执仍兼容。
- 结果：已增加 HTTP/CLI preflight，实测不改变状态 revision；越权、受保护路径及提交后二次范围校验通过，审核回执持久保存完整差异。
- 状态：[x] 已完成

### T3 有界重试原子写入并恢复同一回执结算

- 文件：`runtime/core/storage.cjs`、`runtime/core/dispatcher.cjs`、`runtime/core/desktop.cjs`，新增 `tests/storage-recovery.test.cjs`，必要的 `tests/runtime.test.cjs`、`tests/desktop.test.cjs`。
- 改动：atomic 对 rename 的 EPERM/EBUSY 使用有限重试（建议总等待不超过 300ms）；保留完整临时文件及原目标，不删除旧状态绕过原子替换。其他错误立即返回；用明确错误类型区分存储暂态失败和业务失败。仅清理本次写入拥有的临时文件。
- 改动：已持久回执遇到可恢复存储错误时，不把同一 run 结算成业务 blocked；暂停其派发并由后续 tick/recover 重放同一回执，重放前继续验证身份、候选与完整性。恢复次数有界，耗尽则停在可诊断状态等待处理，不忙循环、不创建新模型 attempt。未持久回执不得推断已提交；重复提交同一内容必须幂等，冲突内容拒绝。
- 改动：记录恢复原因、attemptId、次数和结果；保持 Store.change 只有落盘成功才发布内存状态的顺序。持久化不可用时不可依赖再写 state 才能暂停调度。
- 验收：注入首次 EPERM 后成功，结算一次、审核事件一次、attempt 数不增；持续失败时内存/磁盘保持上次一致状态，队列不继续派发；已有回执重启后恢复一次；非法回执和候选变化仍阻塞；磁盘空间或权限永久错误不伪装成功。
- 结果：已实现 200ms 内的原子替换退避、同回执三轮有界恢复、派发/领取暂停、跨重启恢复及缺失告警补写；故障注入验证不新增模型 attempt、不重复结论和告警。
- 状态：[x] 已完成
